## Как сохранить вывод команды в файл?

```yaml
type: ConsoleExercise
key: 07a427d50c
xp: 100
```

Все инструменты, с которыми вы познакомились до сих пор, принимают имена входных файлов в качестве аргументов.
Большинство из них не предусматривают опцию для указания выходного файла — в этом просто нет необходимости.
Вместо этого можно использовать **перенаправление**, чтобы сохранить вывод любой команды в нужное место.
Если выполнить эту команду:

```{shell}
head -n 5 seasonal/summer.csv
```

на экран будут выведены первые 5 строк летних данных.
Если же выполнить такую команду:

```{shell}
head -n 5 seasonal/summer.csv > top.csv
```

на экране ничего не появится.
Вместо этого вывод `head` будет записан в новый файл `top.csv`.
Посмотреть содержимое этого файла можно с помощью `cat`:

```{shell}
cat top.csv
```

Знак «больше» `>` указывает оболочке перенаправить вывод `head` в файл.
Он не является частью команды `head` —
этот символ работает с любой командой оболочки, которая производит вывод.

`@instructions`
Используйте `tail` вместе с перенаправлением, чтобы сохранить последние 5 строк файла `seasonal/winter.csv` в файл `last.csv`.

`@hint`
Используйте `tail -n 5`, чтобы получить последние 5 строк.

`@pre_exercise_code`
```{python}

```

`@solution`
```{shell}

```

## Как лучше объединять команды?

```yaml
type: ConsoleExercise
key: b36aea9a1e
xp: 100
```

Использование перенаправления для объединения команд имеет два недостатка:

1. После работы остаётся много промежуточных файлов (например, `top.csv`).
2. Команды, необходимые для получения итогового результата, разбросаны по нескольким строкам истории.

Шелл предоставляет другой инструмент, который решает обе эти проблемы сразу, — **пайп** (pipe).
Для начала снова запустите `head`:

```{shell}
head -n 5 seasonal/summer.csv
```

Вместо того чтобы перенаправлять вывод `head` в файл,
добавьте вертикальную черту и команду `tail` *без* имени файла:

```{shell}
head -n 5 seasonal/summer.csv | tail -n 3
```

Символ пайпа указывает шеллу использовать вывод команды слева
как входные данные для команды справа.

`@instructions`
С помощью `cut` выберите все названия зубов из столбца 2 файла `seasonal/summer.csv` с разделителем-запятой, затем передайте результат в `grep` с инвертированным совпадением, чтобы исключить строку заголовка со словом "Tooth". *Команды `cut` и `grep` подробно рассматривались в главе 2, упражнениях 8 и 11 соответственно.*

`@hint`
- Первая часть команды имеет вид `cut -d field_delimiter -f column_number filename`.
- Вторая часть команды имеет вид `grep -v thing_to_match`.

`@pre_exercise_code`
```{python}

```

`@solution`
```{shell}
cut -d , -f 2 seasonal/summer.csv | grep -v Tooth
```

`@sct`
```{python}
Ex().multi(
    has_cwd('/home/repl'),
    has_expr_output(incorrect_msg = 'Вы передали результат `cut -d , -f 2 seasonal/summer.csv` в `grep -v Tooth` с помощью `|`?'),
    check_not(has_output("Tooth"), incorrect_msg = 'Вы исключили строку заголовка `"Tooth"` с помощью `grep`?')
)
Ex().success_msg("Отличное использование конвейера! Возможно, это первый раз, когда вы использовали `|`, но определённо не последний!")
```

Вы можете объединять любое количество команд в цепочку.
Например,
следующая команда:


1. выберет первый столбец из данных о весне;
2. удалит строку заголовка, содержащую слово "Date";
3. выберет первые 10 строк с фактическими данными.

## Как указать сразу несколько файлов?

```yaml
type: ConsoleExercise
key: 602d47e70c
xp: 100
```

Большинство команд оболочки работают сразу с несколькими файлами, если передать им несколько имён.
Например, чтобы получить первый столбец из всех файлов сезонных данных одной командой, можно написать:

```{shell}
cut -d , -f 1 seasonal/winter.csv seasonal/spring.csv seasonal/summer.csv seasonal/autumn.csv
```

Однако вводить имена множества файлов снова и снова — не лучшая идея:
это отнимает время, и рано или поздно вы либо пропустите какой-нибудь файл, либо укажете его дважды.
Чтобы упростить работу, оболочка позволяет использовать **шаблоны подстановки** (wildcards) — указывать список файлов с помощью одного выражения.
Самый распространённый шаблон — `*`, который означает «любое количество любых символов».
С его помощью команду `cut` выше можно сократить до следующего вида:

```{shell}
cut -d , -f 1 seasonal/*
```

или:

```{shell}
cut -d , -f 1 seasonal/*.csv
```

`@instructions`

Вместо того чтобы указывать полные имена файлов, используйте шаблон подстановки.

`@hint`
- Команда имеет вид `head -n number_of_lines filename_pattern`.
- Например, чтобы найти файлы в директории `a`, начинающиеся с `b`, используйте шаблон `a/b*`.

## Какие ещё символы подстановки можно использовать?

```yaml
type: PureMultipleChoiceExercise
key: f8feeacd8c
xp: 50
```

В оболочке есть и другие символы подстановки,
хотя они используются реже:

- `?` соответствует одному любому символу: например, `201?.txt` совпадёт с `2017.txt` или `2018.txt`, но не с `2017-01.txt`.
- `[...]` соответствует любому одному символу из тех, что указаны в квадратных скобках: например, `201[78].txt` совпадёт с `2017.txt` или `2018.txt`, но не с `2016.txt`.
- `{...}` соответствует любому из шаблонов, перечисленных через запятую в фигурных скобках: например, `{*.txt, *.csv}` совпадёт с любым файлом, имя которого заканчивается на `.txt` или `.csv`, но не на `.pdf`.

<hr/>

Какое выражение совпадёт с `singh.pdf` и `johel.txt`, но *не* совпадёт с `sandhu.pdf` и `sandhu.txt`?

`@hint`
Проверьте каждое выражение поочерёдно для каждого имени файла.

`@possible_answers`
- `[sj]*.{.pdf, .txt}`
- `{s*.pdf, j*.txt}`
- `[singh,johel]{*.pdf, *.txt}`
- [`{singh.pdf, j*.txt}`]

`@feedback`
- Неверно: `.pdf` и `.txt` — это не имена файлов.
- Неверно: это выражение будет соответствовать `sandhu.pdf`.
- Неверно: выражение в квадратных скобках соответствует только одному символу, а не целым словам.
- Верно!

## Как отсортировать строки текста?

```yaml
type: ConsoleExercise
key: f06d9e310e
xp: 100
```

Как следует из названия,
`sort` упорядочивает данные.
По умолчанию сортировка выполняется в алфавитном порядке по возрастанию,
но флаги `-n` и `-r` позволяют сортировать числа и изменять порядок на обратный,
флаг `-b` игнорирует ведущие пробелы,
а `-f` **с**кладывает регистр (то есть делает сортировку нечувствительной к регистру).
В конвейерах часто сначала используют `grep`, чтобы отфильтровать ненужные записи,
а затем `sort`, чтобы упорядочить оставшиеся.

## Как удалить повторяющиеся строки?

```yaml
type: ConsoleExercise
key: ed77aed337
xp: 100
```

Ещё одна команда, которую часто используют вместе с `sort`, — это `uniq`.
Она удаляет повторяющиеся строки, но только *соседние*.
Если файл содержит:

```
2017-07-03
2017-07-03
2017-08-03
2017-08-03
```

то `uniq` выведет:

```
2017-07-03
2017-08-03
```

Но если содержимое файла такое:

```
2017-07-03
2017-08-03
2017-07-03
2017-08-03
```

то `uniq` выведет все четыре строки.
Причина в том, что `uniq` рассчитана на работу с очень большими файлами.
Чтобы удалять несоседние дубликаты, команде пришлось бы хранить весь файл в памяти
(или как минимум все уникальные строки, встреченные до этого момента).
Удаляя только соседние дубликаты, `uniq` держит в памяти лишь последнюю уникальную строку.

`@instructions`
Составьте конвейер, который выполняет следующие действия:

Оболочка позволяет перенаправить вывод последовательности команд, соединённых конвейером:

```{shell}
cut -d , -f 2 seasonal/*.csv | grep -v Tooth > teeth-only.txt
```

Однако `>` должен стоять в конце конвейера.
Если попытаться использовать его в середине, вот так:

```{shell}
cut -d , -f 2 seasonal/*.csv > teeth-only.txt | grep -v Tooth
```

то весь вывод команды `cut` будет записан в файл `teeth-only.txt`,
и для `grep` не останется никаких данных —
команда будет бесконечно ждать ввода.
